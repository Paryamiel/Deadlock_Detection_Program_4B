BEGINNER-FRIENDLY GUIDE

How to Use the Deadlock Detection & Analysis Laboratory

Welcome to the Concurrency Laboratory. This interactive guide explains operating system deadlocks in simple, clear terms, shows you how to read the visual graph, and teaches you how to test and resolve deadlocks step-by-step.

🚦

1. What is a Deadlock?

Imagine a 4-way road intersection where four cars arrive at the exact same moment. Each car moves forward slightly and blocks the next car. Nobody can move, and nobody can back up. That is a Deadlock.

In Operating Systems: Two or more programs (Processes) get stuck forever because each program holds a resource that another program needs to finish.
🧩

2. Reading the Graph Symbols

  • P0
    Circle = Process: An active program or thread running in the computer (e.g. P0, P1, P2).
  • R0
    Rectangle = Resource: An asset that processes need, such as a printer, file lock, or memory (e.g. R0, R1).
  • →
    Resource → Process Arrow: The process is currently holding (owning) an instance of this resource.
  • →
    Process → Resource Arrow: The process is requesting and waiting for this resource.
  • ↻
    Crimson Pulsing Arrows: A circular wait cycle! This confirmed loop means the system is in an active deadlock.
⚡

3. Two Detection Phases

This simulator checks for problems across both essential phases:

PRIOR TO ALLOCATION:

Test a request before giving it to a process to see if it would create an unsafe state.

DURING EXECUTION:

Detect active circular wait cycles in real-time using graph algorithms.

§ 2.0 Step-by-Step: How to Interact with the Simulator
STEP 1

Pick a Preset or Click "Random"

Choose Case I (Safe), Case II (Risk), Case III (Deadlock), or the Random Scenario button. The graph instantly centers and fits the canvas so everything is visible right away!

STEP 2

Drag and Move Nodes Freely

Click and drag any Process circle or Resource rectangle with your mouse or finger to move it wherever you like. The dependency arrows will follow smoothly.

STEP 3

Read the Live Graph Interpretation

Check Figure 1.1 right below the graph canvas. It describes what is happening in plain English (e.g. "P1 holds R1 and requests an instance to R2").

STEP 4

Test a Request Before Granting

In Experiment 1, pick a process, choose a resource, and click "Evaluate Request Safety". The system will tell you if granting it is safe or if it triggers a deadlock!

STEP 5

Edit Numbers in Table 1.0

Want to test your own numbers? Type new values directly into the Available, Allocated, or Requested input boxes in Table 1.0.

STEP 6

Break Deadlocks with One Click

If a deadlock occurs, click the red "Preempt Contested Resource" button. The simulator will take back the contested resource from the optimal victim process and restore safety!
